## Browser UI (ADR-073)

The service serves the chat UI at `/` (same host and port as the API). Locally:
`python -m src.service.app --release-root deploy/releases --port 8080`, then open
`http://127.0.0.1:8080/`. With `AIFIN_API_TOKEN` set, enter the token under
"Mã truy cập API" in the sidebar. Set `AIFIN_EXPOSE_PROGRAM=1` to show the generated
Pandas code on answers (analyst deployments only). On a remote host keep the bind
on loopback and reach it with `ssh -L 8080:127.0.0.1:8080 …` or behind the TLS/auth
proxy.

## Release, canary and rollback

```bash
# register + preflight (catalog id, provider-config hash, code fingerprint) + canary; promotes only on success
python -m src.service.release deploy --root deploy/releases --release r2026-10-14 \
  --catalog artifacts/t2p-catalog-v4 --generator provider:deepseek
python -m src.service.app --release-root deploy/releases --port 8080
# after any promotion or rollback, swap the serving release in place
curl -s -XPOST localhost:8080/admin/reload
# manual rollback to the previously served release
python -m src.service.release rollback --root deploy/releases --reason "INC-123: wrong answers"
curl -s -XPOST localhost:8080/admin/reload
```

A failed preflight or canary leaves the serving release untouched and records
`REJECTED` in `deploy/releases/history.jsonl`. During the bake window after a
promotion, `watch_and_rollback` rolls back automatically when a page alert fires.

## Alerts and first response

| Alert | Severity | Meaning | First response |
|---|---|---|---|
| `AifinAvailabilityBudgetBurnFast` | page | 1h and 5m bad-event ratio ≥ 14.4× budget | Roll back if a release went out in the last hours; else check provider status (`reason` label on `aifin_requests_total`) |
| `AifinAvailabilityBudgetBurnSlow` | ticket | 6h and 30m ratio ≥ 6× budget | Look at the top `reason` values; capacity or provider limits |
| `AifinAnswerLatencySLO` | ticket | >10% of answers slower than 8 s | Provider latency, sandbox saturation (`aifin_in_flight`) |
| `AifinNotReady` | page | no release loaded or catalog mismatch | `GET /readyz`; reload or roll back |
| `AifinOverloaded` | ticket | admission control returned 503 | Scale out hosts; keep M7 ≤ 32 workers per host under NsJail |
| `AifinSandboxSecurityEvent` | ticket | generated code attempted a denied capability (contained) | Read the request's history directory; it never ran outside the sandbox |

Bad events for availability are HTTP 5xx (including 503 overload) and `FAILED`
answers with an infrastructure, provider or sandbox-resource reason. Correct
refusals (`NO_DATA`, `UNSUPPORTED`, `NEEDS_CLARIFICATION`) are good events.

## Drill

`python -m src.service.run_reliability_eval` replays recorded model programs
through the real service, pipeline and sandbox and exercises canary rejection,
overload, a provider outage, the page alert, automatic and manual rollback.
